# Shopy Store V4 — Smart Commerce Update

نسخة تطوير متقدمة مبنية على **Shopy Store V3.1**، وليست مشروعًا جديدًا. الهدف تحسين رحلة شراء العميل وتجربة المنتج والأدمن مع **الحفاظ على SQLite والأوامر السابقة**.

**الحالة:** تطوير واختبار محلي. غير جاهز للإطلاق العام وجمع بيانات عملاء حقيقية قبل فحص الأمان والاستضافة والمخزون والعناوين وسياسة الخصوصية والامتثال لخدمات الدفع/التوريد.

## المميزات المنفذة

1. **Smart Checkout:** العميل يرى سعر المنتجات والشحن والإجمالي كل على حدة؛ الواجهة تستعلم عن `/api/shipping-quote` بدل الاعتماد على قيمة شحن مدخلة في HTML فقط. الخادم يعيد حساب الأسعار والخيارات قبل حفظ الطلب. الأدمن يستطيع تحديد سعر محافظة أو مدينة أو منطقة (الأولوية: منطقة ← مدينة ← محافظة). لا تزال أسماء المدن والمناطق نصية وتتطلب تطابقًا تامًا مع إعدادات الأدمن، وليس لدينا قائمة رسمية كاملة لجميع مراكز مصر؛ تحقق من تعرفة الشحن قبل النشر.
2. **تجربة منتج أفضل:** معرض الصور والفيديو الموجود سابقًا، مع تكبير صور قابل للإغلاق، خيارات المنتجات الفردية، عرض منتجات ذات صلة من نفس القسم أولًا، ومقارنة ما يصل إلى 3 منتجات في `/compare`.
3. **مساعد شراء في `/assistant`:** الوضع الافتراضي مجاني قائم على مطابقة الكلمات وميزانية العميل والاختيار من منتجات المتجر فقط. **هذا ليس نموذج AI توليدي في الوضع الافتراضي.** يمكن تشغيل نموذج ذكاء اصطناعي محلي عبر Ollama اختياريًا؛ إذا لم يعمل يتم الرجوع للترشيحات المجانية. لا يتم إرسال بيانات العملاء الشخصية إلى نموذج الذكاء.
4. **تحليلات للأدمن:** عدد الطلبات حسب الحالة، مصادر UTM للحملات، قيمة الطلبات المسجلة **وليست إيرادات أو أرباحًا محصلة**. تكلفة المورد للمنتج والشحن اختيارية وسرية؛ يقدَّر هامش الطلب فقط إذا كانت جميع التكاليف مدخلة، وقبل مصاريف الإعلانات والتشغيل والمرتجعات.
5. **Integrations Center:** قسم واضح للأدمن لحالة COD، والربط المستقبلي مع بوابات الدفع وصفقة Safka وإشعارات WhatsApp. **لم يتم تفعيل بوابة دفع أو صفقة أو إرسال خارجي جديد.** النموذج يتطلب اعتماد API/حساب موثق واختبارات وموافقة المالك. أضف رقم دعم عام وإيميل الاستفسارات من الأدمن؛ لا يُستخدم رقما إشعارات واتساب الخاصان كجهة دعم عامة.
6. **الكتالوج:** تصفية حسب القسم، وهو قابل للتعديل عند إنشاء وتعديل المنتج. لا تظهر عروض أو بانرات افتراضيًا.

**متعمد عدم تنفيذه:** «تتبّع الطلب بدون حساب» بناءً على اختيار المالك. العميل يستطيع الشراء كزائر ويصل لصفحة نجاح طلبه في نفس الجلسة؛ لا توجد صفحة بحث عامة برقم طلب.

## تحديث جهاز Windows من V3.1 أو نسخة V3 Dual WhatsApp

1. **أغلق المتجر القديم** بـ `Ctrl+C` من نافذة CMD الخاصة بالسيرفر.
2. احتفظ بنسخة احتياطية كاملة من المجلد القديم (المطلوب خصوصًا: `shopy.db` و `static/uploads` وملف `.env` الخاص إن وجد).
3. فك `Shopy_Store_V4_Smart_Commerce.zip` إلى مجلد **جديد** ثم انسخ `shopy.db` إلى نفس مكان `app.py` الجديد. انسخ محتويات مجلد `static/uploads` أيضًا، بنفس المسار. **لا تنسخ كود Python أو HTML أو CSS القديم فوق التحديث.**
4. لو تستخدم `.env` في الإصدار القديم، راجع الإعدادات وانقل ما تحتاج إليه إلى `.env` جديد على جهازك، دون وضع أسرار في المحادثة أو مشاركة الملف.
5. افتح CMD داخل المجلد الجديد ونفذ:

```cmd
py -m pip install -r requirements.txt
py app.py
```

6. افتح المتجر `http://127.0.0.1:5000/` — تسجيل الدخول اختياري للعميل. لوحة الأدمن `http://127.0.0.1:5000/admin`.
7. إذا أنشأت أدمن في الإصدارات السابقة لا تعيد تشغيل `create_admin.py`؛ سيبقى حسابك في ملف قاعدة البيانات المنسوخ.
8. بديلًا عن الأمرين يمكن تشغيل `start_windows.bat` بعد حفظ نسخة احتياطية ونقل البيانات.

**قاعدة البيانات:** تتم عمليات ترحيل إضافية تلقائيًا عند بداية `app.py`؛ تبقى سجلات المستخدمين والطلبات والمنتجات القديمة كما هي. الهامش المتوقع للطلبات القديمة لا يُحسب من بيانات مُخترعة.

## تفعيل «AI حقيقي» محليًا (اختياري)

يدعم الإصدار وضعين، والوضع الافتراضي لا يحتاج أي تثبيت إضافي:

- `SHOPY_ASSISTANT_ENGINE=rules`: نظام مجاني سريع لا يحتاج إنترنت أو نموذج AI.
- `SHOPY_ASSISTANT_ENGINE=ollama`: يُرسل **فقط نص بحث العميل والمنتجات العامة** إلى Ollama على جهازك، عبر `127.0.0.1:11434`، ويطلب قائمة أرقام منتجات. لا يقبل أي منتج ليس مسجلًا في قاعدة البيانات. إذا لم يكن النموذج متاحًا خلال 5 ثوانٍ يعود إلى `rules`.

إذا رغبت في الوضع الثاني، ثبت Ollama بنفسك من موقعه الرسمي، حمّل نموذجًا مناسبًا لقدرة الكمبيوتر، ثم عدّل ملف `.env` المحلي:

```env
SHOPY_ASSISTANT_ENGINE=ollama
SHOPY_OLLAMA_MODEL=llama3.2
```

لا يتم تثبيت Ollama أو تحميل نموذج AI ضمن ZIP. استهلاك الذاكرة والأداء يختلفان حسب جهازك، ولا ضمان لجودة الترشيحات التوليدية. لا يوجد مفتاح API مدفوع مطلوب للـ Ollama المحلي.

## صفقة Safka — إمكانيات الربط الفعلية وحدود الإصدار

التوثيق العام الرسمي: https://public-api-docs.safka-eg.com/

بحسب صفقة، الـ Public API يتيح قراءة الكتالوج وتفاصيل المنتجات، قائمة أسعار الشحن، وإنشاء الطلبات باستخدام مفتاح `api-safka-key` بعد موافقة المسوق على الربط. **التحديث V4 لا يرسل أي طلب إلى صفقة تلقائيًا** ولا يستورد منتجات بدون حساب أو إذن. الربط الفعلي يتطلب مراجعة مخطط المنتجات والعناوين والشحن وشروط العمولة والسعر والطلبات والمدفوعات والمرتجعات والهوية التجارية. لا تضع مفاتيح الخدمة داخل HTML أو JS أو الكود المرفوع للعامة.

## الدفع الإلكتروني

COD هو طريقة الدفع العاملة. مركز الربط يعرض موضع بوابة الدفع المستقبلية، لكنه ليس API دفع حقيقيًا؛ تفعيله لاحقًا يتطلب حساب تاجر، مفاتيح سرية، طلب دفع من السيرفر، تحقق Webhook أصلي، منع الطلبات المكررة، حالات دفع منفصلة، واختبارات Sandbox مع مزوّد معتمد. لا تعتمد على صفحة نجاح العميل كدليل على الدفع.

## الاختبارات

بعد تثبيت المتطلبات على جهازك:

```cmd
py -m unittest discover -s tests -v
```

تتضمن اختبارات V4 للأسعار حسب المنطقة، الشراء بأسعار الخادم، المقارنة، مساعد الترشيحات، مصدر حملة UTM، بيانات التواصل، صلاحيات الأدمن، وترحيل قاعدة البيانات.

**ما تم التحقق منه في بيئة الإنشاء:** فحص صياغة Python، تحليل قوالب Jinja2، واختبار مستقل لتحديث قاعدة بيانات قديمة والمحافظة على السجلات وقواعد اختيار أسعار الشحن. **ما لم يمكن تشغيله هنا:** اختبارات Flask integration / HTTP end-to-end، لأن Flask وWerkzeug غير مثبتين في بيئة الإنشاء ولا يمكن تنزيلهما منها. لا تدّعِ أن هذه الاختبارات نجحت قبل إجرائها على جهازك.

## مهام إنتاجية معلّقة

- تأمين جلسات المستخدمين والحد من محاولات الدخول والتحقق الشامل من وسائط الرفع وتسجيل الأحداث ومراجعة تهديدات الويب.

لا يوجد في الملف أي مفاتيح سرية، ولا تُنشر أرقام إشعارات الطلبات الخاصة للعموم.
